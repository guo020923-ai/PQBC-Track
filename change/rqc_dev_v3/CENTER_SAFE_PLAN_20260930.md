# 中心安全型输出细化：方法、证据与训练边界

## 证据链，而非再次盲目换融合公式

1. JQ/BQ的候选重排序没有在正式TNL2K上获得正收益。
2. 局部框细化在固定开发缓存有少量改善，但将新框写回内部状态时，开发TNL2K平均IoU明显下降；输出隔离则缓解。因此不再用细化框改变搜索裁剪或在线prompt。
3. 新增相对原框的IoU损害约束，完整20条开发轨迹相对native的AUC从+0.083提高到+0.130，但LaSOT Precision仍约-1.06。
4. 对已保存的预测做图像坐标下的事后分解：只改变尺寸，在LaSOT/TNL2K的AUC分别-0.046/-0.074；只改变中心分别+0.144/+0.262。这不是独立训练消融，不代表部署结果，但支持取消尺寸修正，而不是继续增大尺寸限幅。

## 当前修改

- CenterSafeRefiner：288维原Head定位特征 → 64维MLP → 2维中心残差，19202参数。
- 原响应选择索引和原框宽高保持不变；中心变化相对原框宽高限幅10%，末层零初始化。
- 特征与原框detach，Backbone/Head不接收新损失梯度；不启用旧ERC或候选重排序。
- 推理只修正返回框，内部跟踪状态、搜索裁剪、prompt更新保持native路径。
- 训练保留2GIoU +5图像归一化L1、相对原框IoU损害项；新增中心损害项：
  `mean(ReLU(log1p(||c_ref-c_gt||² / diag_gt²) - log1p(||c_base-c_gt||² / diag_gt²).detach))`。
- 两项损害权重均为预先固定1，不按视频/数据集设置，不以GT决定测试动作。log1p限制原本已丢失目标的大误差对损失的支配。
- 不承诺不发生有害修正：损失是平均监督，不是每帧正确性的保证。原图边界clip仍可能使输出宽高变化，不能说clip后尺寸严格不变。

## 已完成与正在做

合成/真实fit64检查：零残差恢复、crop宽高严格保持、有限非零梯度、未变/改善中心惩罚0、有害中心惩罚>0、零点额外梯度0、上游和GT梯度隔离。

固定80fit/20dev缓存对照：20轮，每轮50批，batch64，lr1e-4，seed20260930，只评末轮。缓存末轮两域平均IoU增益：LaSOT +0.001708、TNL2K +0.003434；有害比例约8.34%，未见严重单帧损害。现进行全部20条开发轨迹的原状态等价性与官方定义指标检查。

## 不能混淆的部分

- 这些样本来自训练源的开发划分，不是官方测试集；开发AUC不能作为论文正式结果。
- 当前训练缓存来自JQ Epoch30，不是官方Epoch300。不能把相对JQ原轨迹增益说成相对官方baseline的增益。
- 40条旧确认集已经用于先前方案反馈，不再当作新结构的独立泛化证明。
- 官方Epoch300接口已严格加载检查：48帧，零残差最大坐标差约0.000092像素；没有更新官方权重。
- 当前仅是独立原型，没有静默修改正式registry、actor、tracker、数据源或历史YAML。论文定义应改为“输出定位细化”，不能继续声称“只重排序、不移动框”。

## 正式30轮的条件

若完整开发帧的收益及核心指标改善，固定该结构进入官方初始化的受控30轮实验，而不是继续搜索第三种结构。先接入独立训练/测试入口，检查官方权重、冻结参数/BN状态、训练与测试坐标和clip一致性及真实batch反向；不得用本缓存小训练冒充每轮30000样本的正式训练。正式数据和采样规模的变化必须明示，不能悄悄替换。

30轮仍是效果验证，不是最终论文轮数；工程可训练不等于一定涨点。
